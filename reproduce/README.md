# Manuscript reproduction

The outputs under `reference_results/branch_aware_campaign/` are the final
regenerated internal publication results after the normalized Pareto-metric and
endpoint-excluded periodic-domain corrections. The adapted neural fractional-discovery framework
and optimiser-only outputs are stored under `reference_results/yu_framework_comparison/`.
They are the reference values used by the final manuscript.

To reproduce the complete campaign independently from the package root, run:

```bash
bash run_branch_aware_campaign.sh results/normalized_metric_final 5
```

The final argument controls independent worker processes; the reported campaign
used five. Runtime-table rows were generated by uncached serial single-seed runs
with thread counts capped by the driver.

## Everything at once (full experiment budget)

To regenerate the internal tables and figures in one go at full experiment budgets (5 seeds; differential evolution with SciPy
population multiplier $7$ and $24$ generations; noise $0/1/5/10/20\%$):

```bash
# from the package root
reproduce/run_all.sh                          # default: 2 parallel workers
reproduce/run_all.sh --jobs 4                 # choose the number of independent workers
reproduce/run_all.sh -j 4                     # equivalent short form
FPDE_REPRO_JOBS=4 reproduce/run_all.sh         # equivalent environment control
reproduce/run_all.sh --figdir /path/to/paper/figures   # write figures into the manuscript
reproduce/run_all.sh --smoke                  # ~1 min toolchain self-test (Burgers only)
reproduce/run_all.sh --fast                   # quick diagnostic, not suitable for reported results
```

`run_all.sh` sets `PYTHONPATH` to the package automatically and can be invoked
from any directory; if it is run from outside the package, set
`FRACTIONAL_PARETO_DIR` to the package directory. The worker count must be a
positive integer. The command-line forms `--jobs N`, `--jobs=N`, and `-j N`
override `FPDE_REPRO_JOBS`; the default is 2. Parallel workers are used for the
independent shared-cache runs and the weak-row sensitivity stage, while BLAS
thread counts remain capped at one per worker. The individual scripts can also
be run directly, as below.

## Appendix experiments (current Tables 16, 18, and 19)

`run_all.sh` also regenerates the three appendix experiments; they can be run individually:

```bash
PYTHONPATH=. python3 reproduce/make_ksens.py       # Appendix F: weak-row (K) sensitivity + conditioning
PYTHONPATH=. python3 reproduce/make_forward.py     # Appendix H: forward-model validation (e_field)
PYTHONPATH=. python3 reproduce/make_equations.py   # Appendix I: representative discovered equations
```

Each accepts `--fast` for a quick check. `make_ksens.py` varies the number of weak
rows K (and reports the condition number of the weak design); `make_forward.py`
integrates each discovered equation and reports the normalised field error against
the clean reference (with a true-parameter discretisation floor); `make_equations.py`
prints the representative discovered equation next to the truth (median-error-seed
rule, or `--seed` to fix). Outputs: `results/table_ksens.{csv,tex}`,
`results/table_forward.{csv,tex}`, `results/table_equations.{csv,tex}`.

## Proposition 1 variance-scaling check

The grid-refinement rates used in Proposition 1 can be checked independently:

```bash
python3 reproduce/check_variance_scaling.py
```

The default deterministic run uses five grids and 2000 Gaussian-noise fields per
grid. It should report a weak-feature log--log slope close to `-2` and a
pointwise slope close to `2*beta` (`3` for the default `beta=1.5`).


## Additional mathematical diagnostics

```bash
PYTHONPATH=. python reproduce/check_operator_convergence.py
PYTHONPATH=. python reproduce/check_nonlinear_bias.py
PYTHONPATH=. python reproduce/profile_temporal_order.py
```

`check_operator_convergence.py` tests an analytic periodic Riesz eigenfunction and the expected Caputo--L1 convergence rate. `check_nonlinear_bias.py` compares additive and multiplicative trace-bias formulas for nonlinear weak features with Monte Carlo estimates. `profile_temporal_order.py` profiles the held-out temporal-order objective on the correct Riesz support using clean, fully noisy, clean-initial-slice, target-only-noise, and library-only-noise arms. It is an oracle diagnostic and is not used by the discovery algorithm. The corresponding reference outputs are archived under `reference_results/`.

## Requirements

Run from the repository root so the package modules are importable. A clean
environment sufficient to generate every table and figure is:

```bash
pip install -r requirements_all.txt   # numpy/scipy/pandas/matplotlib/tqdm + SciencePlots
```

`reproduce/make_tables.py` needs only the base requirements. Figure generation
uses the LaTeX-enabled SciencePlots `science` style for consistent typography
across manuscript Figures 2--4. The optional `SciencePlots` package is declared in
`requirements_all.txt` and `requirements_optional.txt`; an exact copy of the core
style file is also bundled under `reproduce/styles/`. A working LaTeX installation
(with `amsmath` and `amssymb`) is required to regenerate the figures.

## Notes

* `--fast` reduces the differential-evolution budget and the number of seeds and
  noise levels so the scripts finish in a few minutes; the paper-scale numbers
  require the default (no `--fast`) settings and take longer.
* The robustness experiment runs the proposed **weak** framework
  (`run_weak_pareto_discovery`) and the **strong-form** framework
  (`run_pareto_discovery`, the pointwise library) under the *same* best-subset
  Pareto-DE selector. The Strong-vs-Weak comparison in the robustness table
  also folds in Weak-Pareto's exact-order polishing and full-data refit; the
  Strong Pareto vs Weak Pareto (no polish) rows of the ablation isolate the
  candidate-library effect alone.
* All runs use truth-agnostic uniform order grids
  (`with_uniform_order_grids`) together with the exact-order refit. Direct
  evaluation at the polished orders removes interpolation error from the final
  conditional refit, but the selected support, temporal mode, and optimisation
  basin can still depend on the grid and search trajectory.
* `--only {main,rd_noise,robustness,progress,runtime,burgers,appendix,conditioning}` (tables) and
  `--only {robustness,pareto,burgers}` (figures) regenerate a single object.

## Superunit Caputo branch diagnostic

The manuscript reports a separate semi-analytic fixed-support branch/order
diagnostic with a true temporal order in `(1, 2)`:

```text
D_t^1.65 u = 0.12 D_x^2 u,
```

with zero initial velocity.  The generator evolves each Fourier mode with a
Mittag--Leffler function, so it does not reuse the L1 temporal discretisation
used by the discovery evaluator.

A quick clean/noisy software check is:

```bash
PYTHONPATH=. python reproduce/smoke_superunit.py \
  --outdir results/superunit_smoke
```

The smoke test fixes the one-term linear support and searches the temporal
branch, temporal order, and spatial order. It is a software check rather than
the reported five-seed result. The full comparison with the matched strong-form
baseline is reproduced with:

```bash
PYTHONPATH=. python reproduce/run_superunit_experiment.py \
  --outdir results/superunit_final --jobs 5
```

By default this evaluates 0%, 0.5%, and 1% multiplicative-uniform noise. The
primary protocol deliberately fixes the one-term support, so it is a superunit
branch/order diagnostic rather than unrestricted support discovery. Its weak
target uses the composed matrix `L1(alpha-1) @ D1`; the transposed temporal
weights are concentrated at the first two samples, which is documented as an
implicit initial-rate treatment rather than a derivative-free boundary. The
final reported outputs are archived under `reproduce/reference_results/superunit_final/`.
